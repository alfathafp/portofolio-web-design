# Anti-Slop & High-Signal Engineering Standard

## 1. Vocabulary & Tone Constraints
- **Banned Words**: Never use AI filler words (`delve`, `testament`, `tapestry`, `seamlessly`, `revolutionize`, `game-changer`, `synergy`, `holistic`, `paradigm shift`, `unleash`, `elevate`, `foster`, `pivotal`, `embark`).
- **Tone**: Speak and write like a sharp, pragmatic engineering peer. Avoid cheerleading and fluffy marketing language.

## 2. Technical Evidence & Precision
- Never make vague claims like "robust framework" or "blazing fast" without citing the actual architecture, concurrency strategy, test runner, or metric (e.g. latency, execution time, flakiness rate).
- In case studies, strictly follow the Problem -> Architecture -> Code / Telemetry -> Business Impact structure.

## 3. Code & UI Taste
- Write idiomatic, clean, and maintainable code without unnecessary abstraction wrappers.
- Enforce developer-centric dark mode UI (Zinc/Carbon backgrounds, Emerald/Cyan functional accents, crisp typography) rather than generic AI gradient templates.
